SNOW lives in the GitHub repository `madema-art/snow`. The owner's Windows checkout is `D:\Snow` with Godot at `D:\godot\Godot_v4.7.2-stable_win64.exe`; `Start-Snow.bat` fast-forward pulls `main` and opens the project. Cloud/Linux agents work in their own clone with the official Linux Godot 4.7.2 build (see docs/QA.md). Never hard-code `D:\` paths in game code; use `res://`/`user://`. Do development on a branch and deliver through a pull request; never force-push `main`. Read README, docs/GAME_DESIGN.md, ARCHITECTURE.md, MOUNTAIN.md, AUDIO_DESIGN.md, BUILD_STATUS.md and QA.md before editing.

## Locked design

- ONE rider, ONE enormous mountain, ONE objective: reach the bottom as fast as possible. A good skilled descent of course `massif_v2` takes about FIVE MINUTES; beginners longer, experts faster via routes/tricks/nitro. Never pad the clock, delay the finish, reduce acceleration or add a speed cap to manufacture time.
- `massif_v2`: 9.36 km x 1.2 km, ~3.115 km net drop, five contiguous regions (Summit, Cliffs, Forest, Broken Mountain, Final Descent), multiple natural routes, real gorges/cliffs/forest/gullies, optional jump lines. No checkpoints, invisible walls or X/Z death zones. Riding straight must meet real hazards and fail. Fatality only from physical impact/fall.
- Stationary start; explicit push-off starts time. No NPCs, wildlife, helicopter, opponents, intro, countdown, injury/health, score, music, avalanche or advanced storms.
- Absolutely NO gameplay HUD. Pause/results alone shows hundredth elapsed time, top ten completed times, mappings and resume/restart/quit.
- Left stick always steers, Menu always pauses. Right stick is ONLY the free camera, on snow and in air; it never steers, spins or flips. Defaults: A push/ollie (hold to preload), B nitro, LT brake, RT tuck, X grab, LB/RB spin, D-pad up/down flips, RS click recenter, View restart. Everything except LS/Menu remaps and persists; conflicts swap; fixed UI navigation.
- Board glow is the ONLY nitro indicator. Nitro is forward thrust only (never grip). Landed tricks earn charge (harder/bigger/cleaner pays more, repetition fatigues). EVERY fall instantly clears ALL velocity, speed and nitro and darkens the board; severity scales recovery time; the clock runs during recovery; fatal falls end attempts without records; tumbles are visual only.
- 3840x2160 fullscreen, VSync, 60 FPS cap, 60 Hz physics, no graphics menu, Compatibility renderer.

## Implementation map (details: docs/ARCHITECTURE.md)

`scripts/main.gd` composes: SnowControls, SnowRun, SnowMountain (+SnowAtmosphere, SnowBackdrop, scenery via SnowMeshes), SnowRider (+SnowRiderVisual), SnowCamera, SnowFX, SnowAudio, SnowHaptics, SnowPauseMenu. ALL feel constants live in `scripts/snow_tuning.gd`. Shaders are in `shaders/`. Audio WAVs in `audio/` are generated by `tools/synth_audio.py` (numpy, seeded, original) — edit the tool and regenerate, never hand-edit WAVs. Terrain is 8 m indexed grids in 200 m chunks with identical render/collision triangles; the rider physics reads the same analytic surface data (powder/ice) the terrain shader paints. Hazard layout (trees/rocks) keeps pass-2 seeds; per-chunk static bodies carry `hazard` meta; `SnowMountain.hazards_near()` is the spatial query.

Saves: records `user://snow_records_massif_v2.json`, controls `user://snow_controls_v2.json` (v1 migration kept). Version the records file if course geometry changes enough to affect comparability; never delete old records. Tests use disposable `test_*` files.

Local fixtures and visual captures must be labelled as fixtures. Never claim physical Xbox feel, audio listening, or real 4K/60 performance from cloud runs — the cloud has software GL (llvmpipe) only. Keep docs/BUILD_STATUS.md accurate. Do not commit `.godot/`, `work/`, renders or logs.
